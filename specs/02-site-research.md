# 02 — Исследование djinni.co

Дата исследования: 2026-10-23. Сырые данные: `cache/research/`.

## 1. Доступ и формат данных

- **Полностью серверный рендеринг** — JS не нужен, рендеринг не требуется. Страницы отдаются
  как обычный HTML (с включёнными статическими CSS/JS-бандлами).
- **Аутентификация не нужна** для просмотра списков и отдельных вакансий.
- **robots.txt** (`cache/research/robots.txt`):
  ```
  User-agent: *
  Disallow: /jobs2
  Disallow: /q
  Disallow: /developers
  Disallow: /free-jobs
  Disallow: /set_lang
  ```
  `/jobs/` и `/salaries/` разрешены. Запросы делались с паузами 1–2 с, обычным браузерным UA;
  блокировок не наблюдалось.
- Есть `Sitemap: https://djinni.co/sitemap.xml`.

## 2. Список вакансий `/jobs/`

- **Пагинация**: `?page=N`, **15 вакансий на страницу** (проверено на 3 страницах), всего
  ~415 страниц ≈ **6200 активных вакансий** (на 2026-10-23).
- **Фильтры через GET-параметры** (работают без JS):
  - `primary_keyword=Java` → 91 вакансия; `React`, `DevOps`, `QA` — аналогично.
  - `all_keywords`, `any_of_keywords`, `exclude_keywords` — составные запросы.
  - `exp_level` — уровни (no_exp, 1y, 2y, 3y, 4y, 5y+).
  - Есть фильтры по типу занятости, локации, категории/направлению (`category`), формату работы.
- **Структура элемента вакансии** (div `job-item` c `id="job-item-<id>"`):
  - заголовок: должность (`job-item__position`), компания, логотип;
  - зарплатный тир `$$` (относительный уровень: $ — ниже среднего … $$$$ — самый высокий);
  - строка метаданных: формат (офис/удалённо/гидрид), страна, required experience,
    уровень English, отрасль/направление (badge);
  - теги (например 🪖 DefTech, «Продуктова компанія»);
  - **полный текст описания** — в `<span class="js-original-text">`, поэтому список вакансий
    уже содержит почти все данные (описание, требования, nice-to-have, язык).
  - ссылка на отдельную страницу: `/jobs/<id>-<slug>/`.
- **JSON-LD в `<head>`**: массив объектов `schema.org/JobPosting` — `category`, `datePosted`,
  `description` (может быть усечён). Для детального разбора — отдельная страница.
- **Структурированных навыков в списках НЕТ** (проверено: `detail-rows` в списках = 0).
  Блок «Необхідний досвід з навичками» — только на отдельных страницах вакансий.

## 3. Отдельная вакансия `/jobs/<id>-<slug>/`

Ключевая находка: **структурированные навыки** — детерминируемый парсинг без LLM.

- **JSON-LD `JobPosting`** (один объект):
  - `title`, `description` (полный текст), `url`, `datePosted`, `validThrough`;
  - `employmentType` (FULL_TIME и т.п.);
  - `experienceRequirements.monthsOfExperience` (число месяцев);
  - `category` (направление: Architect, QA, Project Manager…), `industry`;
  - `jobLocationType: TELECOMMUTE`, `applicantLocationRequirements`;
  - `hiringOrganization` (компания, sameAs);
  - **иногда `baseSalary`** — реальная вилка в USD/месяц (напр. Mobile QA: 800–1200 USD/мес).
    Не у всех вакансий! У большинства — только относительный тир $.
- **Блок «Необхідний досвід з навичками»**:
  ```html
  <div class="detail-rows__line">
    <span class="detail-rows__name">Python</span>   <!-- навык -->
    <span class="detail-rows__value">3 роки</span>  <!-- годы опыта -->
  </div>
  ...
  <span>NumPy, Flask, SQLAlchemy, Docker, Kubernetes</span>  <!-- доп. навыки через ", " -->
  <div id="more_skills_exp">GCP</div>               <!-- свёрнутые через "+ ще N" -->
  ```
- **Вимоги до володіння мовами**: уровни English (A1–C1/Advanced) — в `detail-rows__line`.
- **Sidebar**: требуемый стаж («Виключно від 10 років досвіду»), формат, локация, категория
  («Домен: Healthcare / MedTech»), тип компании.
- **Статистика**: перегляды, отклики за 30 дней, дата обновления — на странице.
- **Вакансия устаревает**: `validThrough` (обычно месяц с публикации) — важно для дедупликации
  и инвалидации.

### 3.1 Статистика конкуренции (добавлено 2026-11-01)

Блок `#job-publication-info` даёт четыре сигналы, три из которых раньше игнорировались:

- **Просмотры/отклики, две строки**: `За 30 днів: 147 переглядів · 8 відгуків` и
  `За весь час: 305 переглядів · 34 відгуки`. Молодые вакансии (без разбивки) отдают одну
  одиночную строку `51 перегляд · 6 відгуків` — тогда 30-дневных значений нет (null).
- **`Активність рекрутера:`** — ровно четыре значения: `Дуже висока`, `Висока`, `Середня`,
  `Низька`. Подпись-подсказка djinni: «На основі того, як часто і як швидко рекрутер відповідає
  на відгуки на цю вакансію». У молодых вакансий блока может не быть вовсе.
- **`Відповідали …`** — относительная подпись (`Відповідали вчора`, `Відповідали 9 годин тому`,
  `Відповідали більше місяця тому`) **плюс точный timestamp в tooltip** того же элемента
  (`title="16:29 14.10.2026"`, локальное время Europe/Kyiv). Относительная подпись
  живёт только в кэшированном HTML, абсолютная дата — стабильна.
- **Кнопка «Огляд кандидатів»** (`hx-get="/api/jobs/<id>/?apply_stats"` в `#applicant_insights`)
  открывает **публичный JSON без авторизации** — это и есть скрытая статистика конкурентов:

  ```json
  {
    "total_applicants": 35,
    "experience_dist": [{"label": "5-10 років", "count": 17, "percent": 100, "is_candidate": false}, …],
    "salary_dist":     [{"label": "$3800-4600", "count": 12, "percent": 100, "is_candidate": false}, …],
    "english_dist":    [{"label": "B2", "count": 18, "percent": 100, "is_candidate": false}, …],
    "top_skills":      [{"name": "Java", "count": 31, "candidate_has": false}, …]
  }
  ```

  Оговорки по данным (проверено на живых ответах):
  - **`percent` — нормировка на максимум, а не доля**: у бакета с максимумом всегда 100.
    Долю считаем сами: `count / сумма(count)` по конкретному массиву.
  - Суммы `experience_dist` / `salary_dist` бывают **меньше** `total_applicants`
    (не все кандидаты указали опыт/ожидания); `english_dist` обычно полная.
  - `is_candidate` / `candidate_has` — флаги для залогиненного пользователя, анонимно
    всегда `false`; в БД не сохраняются.
  - `total_applicants` — текущее число откликнувшихся и может не совпадать с `repliesCount`
    со страницы (разное время снимка / перевыпуск вакансии) — оба значения хранятся раздельно.
  - Ответ приходит и на вакансии, где блока `applicant_insights` на странице нет.
  - Запросы к `/api/` не запрещены `robots.txt` (запрещены `/jobs2`, `/q`, `/developers`,
    `/free-jobs`, `/set_lang`), но идут с теми же паузами 3–8 с, что и остальной скрейп.

  Семплы ответов: `cache/research/applicant-stats-*.json` (см. README этой папки).

## 4. Связанные данные

- **`/salaries/`** — публичная зарплатная аналитика: зарплатные вилки по категориям,
  уровню опыта, формату работы, English level. Полезно как источник для агрегатов (проверить
  возможность скрейпа без авторизации).

## 5. Выводы для архитектуры

1. **Гибридный парсинг** (детерминированно + LLM):
   - детерминированно (cheerio/regex): JSON-LD, структурированные навыки, English level,
     формат/локация, категория, статистика, тир зарплаты;
   - LLM — только для нормализации free-text описаний в таксономию скиллов и для матчинга
     профиль ↔ вакансия (а также рекомендаций «что освоить»).
2. **Двухэтапный сбор**:
   - **Bulk (первичный)**: списки (метаданные, datePosted, описание, dedupe) + **обход всех
     detail-страниц** (~6200 × 1–2 с ≈ 2–3.5 ч) — только там структурированные навыки.
   - **Incremental (по расписанию)**: первые N страниц списков → новые/изменённые → их
     detail-страницы.
   - LLM-нормализация free-text (из описаний) — отдельный слой, нужна не для всех вакансий.
3. **Дедупликация**: по `id` (из ссылки `/jobs/<id>-…/`) + обновление по `datePosted`/`validThrough`.
4. **Фильтра по дате публикации у djinni нет** (в GET-параметрах) — окна «7/30/90 дней»
   фильтруем у себя в БД по `datePosted`.
5. **Rate limiting**: 1–2 с между запросами, паузы при 429/403, ротация User-Agent (TBD),
   счётчик запросов в RunLog.
6. **Язык**: описания смешанные (украинский/английский) — парсер и LLM должны это учитывать.
