## Ключевые решения (зафиксированы)

- **Стек**: Next.js, PostgreSQL + Prisma, Telegram Bot.
- **Аудитория**: старт — личный инструмент; архитектура сразу рассчитана на мультитенантность
  (своя подписка в боте на пользователя, BYOK — bring your own key — доступ к LLM API).
- **Продуктовая модель**: free — пользователь оплачивает анализ своими ключами доступа к API
  моделей; потенциальная платная версия — модели провайдера.
- **Деплой**: сначала локально, в перспективе VPS (возможно OpenNext для упрощения миграции).
- **Язык документов**: русский; идентификаторы и код — английский.

## Ключевые решения (skill gap, см. 06)

- **Гибридная аналитика**: детерминированный слой (co-occurrence, share/lift, веса must=1.0
  / nice=0.5) — ядро; ML-слой (эмбеддинги + HDBSCAN) — фаза 2 с критерием запуска из 06.
- **Окна времени**: 7/30/90 дней (фильтр по `datePosted` в БД — у djinni GET-фильтра по дате нет).
- **Technology page**: свой каталог уровней (junior/middle/senior) + внешние ссылки;
  iframe roadmap.sh заблокирован (`X-Frame-Options: SAMEORIGIN`), лицензия запрещает
  перепубликацию — только personal-use кэш как опция (риск, gate).
- **Сбор**: bulk — обход всех detail-страниц (~6200, структурированные навыки только там);
  incremental — новые/изменённые.

## Ключевые решения (имплементация F1, 2026-10-24)

- **CLI + Prisma сейчас** (Next.js отложен); PostgreSQL 16 в Docker Compose (порт 5433).
- **Скрейп**: случайная пауза 3–8 с (равномерно), backoff 10–160 с на 429/403/5xx; честный UA с
  указанием бота; лимиты запуска `--pages` (default 5) и `--vacancies` (default 5) отдельно.
- **TTL кэша**: страницы списка — 1 день (общая инвалидация, нумерация сдвигается);
  детали вакансий — 7 дней, приоритетнее признака «обновлено на djinni» (`updatedAtDjinni`).
- **Экстракция навыков — только детерминированный слой** (LLM отложен): 3 источника
  (`djinni_structured` → `djinni_extra` → `description_keyword` → `llm_description` —
  LLM-слой опционален и вызывается только при < порога навыков, ADR 0002) + словарь ~200 записей
  с алиасами; нераспознанные имена — `Skill(isCanonical=false)`, отчёт `pnpm skills:unresolved`
  и курация `pnpm skills:promote` (см. implementation/0003).
- **Два представления данных**: Postgres (нормализованное, для приложения) + JSON/CSV-снапшот
  long-format «вакансия×навык» (`cache/analysis/`, для статистики/пандаса/кластеризации/LLM).
- **Рыночная БД без `userId`**: профиль пользователя — отдельная надстройка (см. 0001).

Подробности и обоснования: [implementation/0001-market-pipeline.md](implementation/0001-market-pipeline.md).
